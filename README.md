## 关于 AI 生成内容的特别说明

这份说明很重要，请先读完再使用。

### 1. 部分内容可能不构成「作品」

AI 生成的图片、视频，其著作权地位在各国并不一致：

- **中国**：北京互联网法院在「春风送来了温柔」案中认可了 AI 生成图片的著作权，但前提是使用者能证明自己在提示词设计、参数调整、多轮筛选上的智力投入；苏州「幻之翼透明椅」案则因原告无法复现创作过程而被认定不构成作品。
- **美国**：版权局 2025 年 1 月的报告认为，仅靠提示词不足以构成人类作者身份。

也就是说，**这些图片可能根本不受著作权保护，作者也就无从「授权」**。为了在这种情况下依然给你明确的使用许可，本仓库采用「双轨」声明：

> 就本仓库中**受著作权法保护**的内容，按上表所列协议授权；
> 就依现行法**不构成作品**的内容（例如部分纯 AI 生成图片），作者在此同样授予上述协议范围内的全部使用权限，并承诺不就此主张权利。

这样无论法律怎么认定，你都可以放心使用。

### 2. 本仓库记录的「创作过程」本身是证据

每件作品的 `prompt.md` 与 `meta.json` 记录了提示词迭代、参数、种子、模型版本。这既是复现所需，也是将来主张权利时最关键的原始记录。**请勿删除。** 本仓库的 commit 历史同时提供了可信时间戳。

### 3. 上游条款仍然约束你

作者的协议**不能**覆盖模型与工具的许可条款。使用前请自行确认：

- **底模**：例如 FLUX.1 [dev] 采用非商用许可（其输出可商用，但须遵守条款）；不同底模、不同版本差异很大，`meta.json` 里已记录模型来源；
- **工具**：ComfyUI 本体为 GPL-3.0。本仓库分发的 workflow JSON 属于数据文件，不构成对 ComfyUI 的衍生；但如果你分发修改过的 ComfyUI 代码，须遵守 GPL-3.0。自定义节点各有其协议；
- **闭源服务**：如使用 MiniMax / 海螺等在线服务生成，请核对对应服务条款中的再分发与商用约定。

## 目录结构

```
AIGC_Archive/
├── LICENSE                 # CC BY 4.0 全文（内容默认协议）
├── LICENSES/MIT.txt        # 代码协议
├── CITATION.cff            # 引用格式
├── _templates/             # 新增作品时复制的模板
│   ├── prompt.md
│   └── meta.json
└── prompts/
    └── YYYY-MM-<slug>/     # 一件作品一个目录
        ├── prompt.md       # 提示词、参数、迭代记录
        ├── meta.json       # 结构化元数据
        ├── workflow.json   # ComfyUI 工作流（UI 导出）
        ├── workflow.api.json  # （可选）API 格式，供脚本调用
        └── 01.png          # 成图，多张按 01/02/03 编号
```

命名约定：`YYYY-MM-<slug>`，slug 用小写英文与连字符，例如 `2026-03-spring-portrait`。目录名即作品 ID，请勿在发布后改名（改名会断掉外部引用）。

## 新增一件作品

```bash
cp -r _templates prompts/2026-03-my-work   # 1. 复制模板
# 2. 填写 prompt.md、meta.json
# 3. 放入成图：01.png、02.png …
# 4. 从 ComfyUI 导出工作流：菜单 Workflow → Save（UI 格式）
#    需要脚本调用时再 Export (API)，存为 workflow.api.json
git add prompts/2026-03-my-work && git commit -m "add: 2026-03-my-work"
```

`meta.json` 中的 `human_authorship` 字段请如实填写——它既是维权证据，也让使用者知道哪些环节是人做的。

## 为什么是这套协议

- **内容用 CC BY 4.0**：Creative Commons 官方明确不建议把 CC 协议用于软件，但正是文字、图像这类创作内容的通用选择；它是 GitHub 能自动识别的协议，署名要求也符合「内容回流到 B 站」的诉求。
- **代码用 MIT**：短小脚本不需要 Apache-2.0 的专利条款与 NOTICE 负担，MIT 最省事。
- **没有用 CC0**：CC0 放弃署名，与归档、可追溯的目标冲突。
- **没有用 CC BY-SA / NC**：SA 会让企业用户因「派生边界不清」而回避；NC 不是开源协议，且「非商业」定义模糊，反而挡住正常使用者。若将来要开展商业授权，再单独为示例图开一条支线。
